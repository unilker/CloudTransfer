Google and Microsoft both require an application of your own before any program may reach your files. It is free, takes a few minutes, and is only ever done once — paste the results below and nothing else needs configuring.

Google Drive not set up
  1. Open the Google Cloud Console and create a project.
  2. APIs & Services → Library → enable Google Drive API.
  3. OAuth consent screen → External → add your own address as a test user.
  4. Credentials → Create credentials → OAuth client ID → Desktop app.
  5. Copy the client ID and client secret into the boxes below.
OneDrive not set up
  1. Open the Azure Portal → Microsoft Entra ID → App registrations → New registration.
  2. Account types: personal and work/school.
  3. Redirect URI → platform Mobile and desktop applications → paste the address below.
  4. API permissions → Microsoft Graph → Delegated: Files.ReadWrite, offline_access, User.Read.
  5. Copy the Application (client) ID below. A desktop registration needs no secret.

      How this works, and what it cannot do

      No local copy. Each file is read from Drive in byte ranges, held one chunk at a time in memory, and pushed straight into a OneDrive upload session. Nothing reaches a filesystem, so there is no temporary folder and no partial file left behind.

      Bytes still travel through this process. A true cloud-to-cloud copy is not possible: Google Drive offers no “send to URL” API, and Microsoft retired its “upload from URL” feature. Something has to relay. Run this app on a server or container and your own machine carries no traffic at all.

      Google Docs, Sheets and Slides are converted. Native Google formats have no bytes to copy, so they are exported to .docx/.xlsx/.pptx on the way out. Google caps that export at 10 MB, and files above it are reported as skipped rather than silently dropped. Coming the other way nothing needs converting, since every OneDrive file is already real bytes — except a OneNote notebook, which is a package with no single stream to copy.

      Interrupted transfers resume. OneDrive remembers how much of each upload it holds. After a pause, a crash or a network drop, each file continues from that exact byte instead of starting over.

      Renames are recorded, never silent. Characters OneDrive rejects, duplicate names in one folder and reserved names are all rewritten, and every change appears in the job report.
