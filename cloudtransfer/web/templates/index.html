      How this works, and what it cannot do

      No local copy. Each file is read from Drive in byte ranges, held one chunk at a time in memory, and pushed straight into a OneDrive upload session. Nothing reaches a filesystem, so there is no temporary folder and no partial file left behind.

      Bytes still travel through this process. A true cloud-to-cloud copy is not possible: Google Drive offers no “send to URL” API, and Microsoft retired its “upload from URL” feature. Something has to relay. Run this app on a server or container and your own machine carries no traffic at all.

      Google Docs, Sheets and Slides are converted. Native Google formats have no bytes to copy, so they are exported to .docx/.xlsx/.pptx on the way out. Google caps that export at 10 MB, and files above it are reported as skipped rather than silently dropped.

      Interrupted transfers resume. OneDrive remembers how much of each upload it holds. After a pause, a crash or a network drop, each file continues from that exact byte instead of starting over.

      Renames are recorded, never silent. Characters OneDrive rejects, duplicate names in one folder and reserved names are all rewritten, and every change appears in the job report.
